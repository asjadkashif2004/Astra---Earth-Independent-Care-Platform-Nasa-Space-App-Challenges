Autonomous Space Telemedicine & Research Assistant
Learn what the current application does, how to operate it, and how to explain it honestly. No

Figure U1. Mission overview with fictional crew and source-bound synthetic observations. Actual retained application capture, 9 Nov

What is ASTRA?
ASTRA is an offline-first research prototype for exploring crew health during a space mission. It combines
monitoring, fictional mission scenarios, a selectable 3D body, recorded signal replay, trend research and
local scientific evidence tools. A long communication delay makes clear onboard information and human
oversight valuable.
What you are demonstrating:
 working software with simulated crew data. The six astronauts are
fictional. A real API request does not mean a real sensor measured an astronaut. ASTRA does not
diagnose disease, prescribe treatment or claim flight certification.
Who uses which part?
Crew and mission staff view observations and review alerts. Researchers inspect model evidence and
source quotations. The current login is a local demonstration identity system, not a production identity
service.

Acknowledge correctly
With an acknowledgement-capable role, open the
alert and select its acknowledgement action. Wait
for confirmation. If case preparation is still pending,
wait and retry the visible action. Do not claim
success after a conflict or error.
Why Earth may still show older data
Acknowledgement records a human decision locally. A report then follows the durable communications
queue. Default one-way delay is 12 mission minutes, plus transmission and small jitter; blackout or retry
can delay it further. Acknowledgement, transmission and receipt are separate events. Use
Communications to inspect the queue and Spacecraft/Earth received views. Its privileged synthetic
controls configure delay, bandwidth, loss and blackout; changing a setting does not mean Earth already
received a report.

View signals and replay recordings
Figure U5. Signal archive preserves recording, channel, units and archive time. Actual retained application capture, 9 Nov 2026; not a
new execution.
A 
waveform
 is a series of sampled values drawn over time. Its sampling rate tells you how many values
were recorded each second. ASTRA’s supported demo recordings are explicitly synthetic, not a live
astronaut ECG.
Import and inspect an authorized synthetic recording
1. 
Open Signal archive; confirm the crew selection. Use the built-in synthetic example workflow or select
an already authorized ASTRAWV1 binary / ASTRACSVv1 file.
2. 
Confirm synthetic provenance, then click Generate & import once for the example or import the
selected file with a permitted role. Do not upload real patient files.
3. 
Choose the recording and channel: ECG, PPG or RESP only where that source provides them.
Inspect units, sampling frequency, source identity and timestamps.
4. 
Drag the archive cursor, use start/seek controls and Play/Pause. The chart follows recording time, not
“live sensor” time.
5. 
Inspect missing intervals and quality flags. A gap is unavailable data, not a zero reading or an
interpolated medical finding.
What to expect and what may be unavailable
The compact parser accepts bounded recordings: up to 256,000 bytes, 1–60 seconds, 1–3 channels and
50–500 Hz. A compatible source is required; selecting a cardiovascular region cannot manufacture an
ECG. No validated blood-pressure estimate is inferred from PPG.
History cutoff:
 a recording is visible only when it was known by the selected archive cutoff. After
import the UI can advance an unchanged cutoff and announce that update. An intentionally chosen
historical cutoff remains yours; choose a compatible cutoff to view a newly imported source.
Common errors
No recording: import an eligible synthetic example or show unavailable. Wrong channel: select one
supplied by the recording. Blank signal: check cursor, cutoff and gaps. Denied import: use an authorized
role, not a service token or a file-path workaround. Large or malformed files are rejected cleanly.

limits
Feature / location
How to use it honestly
Crew health: conditional trends
Inspect an available trend and its coverage/horizon. Persistence repeats a last
value; OLS fits a line; Theil–Sen uses a median slope. Missing/stale inputs can
produce UNKNOWN. The legacy trend and full N12 research protocol differ.
Evidence & provenance: N11/N12
Read permitted existing model evidence and saved results. Isolation Forest was
rejected. N12 has zero operational promotions. Do not click fresh Compute, train,
calibrate or evaluate for this presentation.
Research library: in the app
Search the older local knowledge summaries. This screen is not the
independently governed N13 exact-publication corpus interface. Do not equate
summary citations with proven medical answers.
N13/N14: research/backend only
Use the offline CLI below for source verification and exact-window lexical lookup.
No new dedicated NASA-corpus screen is available in the main application.
N15: research/backend only

and positive factual-support rules are inactive. Qwen is not actively answering in
the app.
Health agent: main app
Shows deterministic N02 case summaries and suggested review steps, marked

Prepare the isolated database and browser before judges arrive. Import the authorized synthetic
waveform example and check that the chosen crew has a source. Do not spend presentation time
downloading packages, fitting models or seeking new scientific approvals.

Launch with the page 2 commands; choose Demo administrator. Show Mission overview. Say:
“Six fictional crew members; locally generated observations.”
0:35–1:20
Select CREW-03. Show metric units, source times and quality. Open Scenario lab; start

3:00–3:40

Keys, setup and troubleshooting
Service / setting
Required for this demo?
OpenAI / cloud Qwen / Supabase
No. No supported demo path calls these services or needs their keys.
Hugging Face / NASA API
No runtime token/key. Existing local assets and downloaded-source records
are separate from a new acquisition.
Local Qwen weights
No remote AI key, but native execution still requires current
resource/sandbox approval; presently inactive.
SQLite credentials
None. Local file permissions and safe ASTRA_DB selection matter.
ASTRA_INGEST_TOKEN
Optional service credential for external scalar telemetry ingestion only. Not
needed for the simulator or authorized waveform UI import. Unset means
that service path is disabled.
Configure actual settings in the terminal environment before starting. The server does not establish an
automatic .env loader. Never paste a secret into source code or these PDFs.
Symptom
What to do
npm start / dependency failure
Check the project directory and Node 24.21+ (<25). Retain the prepared
packages/vendor assets. Do not run a blind upgrade or download campaign.
Port 3000 in use
Choose PORT=3001 and open its matching URL. Keep HOST=127.0.0.1.
Backend unreachable / blank page
Read the launch terminal error; check URL/port. Restart the same DB path. If the
old service worker shell persists, reload once online.
Database unavailable
Check ASTRA_DB points to your new writable temp directory. Do not
rename/delete a locked existing database or select a sealed fixture.
No data / UNKNOWN
Check crew, source times, source quality and monitoring readiness. A paused or
missing source can correctly be UNKNOWN.
Scenario unresponsive
Wait for pending operation; inspect current run, clock and role. Do not repeatedly
issue a new Start.
Waveform missing / invisible
Check crew, recording, provided channel, cursor, cutoff and missing intervals.
Import only an eligible synthetic example.
3D fails / WebGL unavailable
Use textual region controls. Check local assets, browser graphics support and
explicit reload after context loss. Coarse LOD can reduce cost.
3D slow / navigation seems delayed
Allow the measured initial 8–9 s remount. Avoid duplicate tabs. Use coarse
quality and reduced motion where appropriate.
AI unavailable
Expected for restricted Qwen, unreviewed support rules and operational N16.
Use permitted lexical lookup or recorded evidence instead.
Logout hidden / session expired
Use the current responsive menu/Logout control; zoom/reflow is supported. 401:
login again. 403: use a permitted role, not a bypass.
