1 · Executive overview

ASTRA explores how a crew and remote support team could inspect health information when connectivity is limited or delayed. The implemented prototype unifies synthetic observations, deterministic monitoring, durable records, 3D navigation, waveform replay and separated research tools. Its research value is the inspectable engineering workflow—not proof of clinical effectiveness.

Intended users include fictional crew participants, mission-control reviewers, a medical-review role and researchers. The current demonstration is local and synthetic; there is no verified live astronaut-device connection. Human acknowledgement controls report queuing. Unavailable evidence remains UNKNOWN or ABSTAIN rather than a fabricated answer.

Maturity: presentation-ready with limitations. N01, N02 and N04 are formally Complete. N03 is Partial. N05–N16 remain In Progress with different engineering qualifications and external gates. This is not a certified medical or flight system.

Name note: this report uses the owner’s requested expansion above. The older primary specification expands ASTRA as “Autonomous Space Telehealth & Resilience Architecture”; the application brands itself ASTRA Command. The repository therefore contains a naming inconsistency, not three separate systems.

2 · What happens when you click?

The frontend is the browser interface. The backend is the local Node process that checks permissions, retrieves or computes information and returns it. An API is the agreed request/response boundary between them. JSON is the text format used for most structured messages.

In app.mjs, the shared api() function calls fetch with the session cookie. The server matches the route and calls the anatomy service. The service returns a projection of eligible stored/source data; opening this view does not create an alert. If you switch crew before the reply arrives, request gates and session/version checks stop old-crew data from replacing the new panel.

5 · SQLite: memory that survives restart

SQLite is a database engine inside the application process. It stores structured records in a local file. This suits an offline prototype because startup does not require a remote account, network connection or separate database server. It does not by itself provide medical certification, encryption or high-availability mission infrastructure.

ASTRA_DB selects the file. The CLI defaults to data/runtime/astra.sqlite; the presentation flow creates a new temporary directory instead. The library’s in-memory default is used by isolated tests, not the ordinary CLI persistence path. Rows often combine indexed IDs/times with a JSON field; waveform chunks store signal bytes as BLOBs.

Table familyPurpose
state, snapshots, health_baselinesRecover engine state and source-bound history; baseline context.
risk_events, agent_cases, comms_messagesPersist detector events, template cases, acknowledgement and delayed reports.
telemetry_points, waveform_sources/chunksScalar observations and bounded original/chunk BLOB signal data.
sleep_sessions, n10_records, checkinsLegacy plus versioned sleep/personal records; privacy is enforced by services.
n09_*, n11_*, n12_*, predictionsScenario runs, research jobs/results/events and separate legacy trends.
sessions, audit_events, schema_versionsHashed sessions, chained audit records and schema history through version 8.

Atomicity, idempotency and cold recovery

transaction() uses BEGIN IMMEDIATE and commit/rollback, so related writes succeed together or fail together. Event IDs and request IDs stop duplicate commitments. WAL mode, foreign-key checks and a busy timeout support durable local work. Many history tables have append-only triggers; mutable state is not universally immutable. Additive schema setup preserves old evidence. A cold restart reconstructs committed state; replaying a result is not permission to rerun a model or worker.

6 · Is the health data real or fake?

“Synthetic” means intentionally generated rather than measured from a person. It is not the same as hardcoding a decorative number. ASTRA’s simulator commits time-stamped observations through real services, drives monitoring rules and supports repeatable replay. That demonstrates software behavior; it does not demonstrate physiology or clinical predictive accuracy.

Data typeWhat the current repository establishes
Hardcoded display-only valuesA fake fixed number would not exercise source/crew/time validation. The accepted monitoring/anatomy workflow reads actual application-generated observations instead.
Deterministic synthetic telemetryThe main six-crew demo uses seeded generation, individual reference distributions, scenario effects, source times and quality states. No physical sensor is needed.
Imported synthetic waveformsThe app accepts its bounded synthetic ASTRAWV1/CSV contract, including authored gaps. These are not authentic live ECG/PPG recordings.
Authentic publications / metadataTwo N13 NASA PDFs plus N07 NASA/OSD metadata are retained research sources. A paper is evidence text, not a live biometric feed.
Authentic BIDMC numericsOne small de-identified PhysioNet numerics CSV is in the approved local archive. It is not the app’s crew feed, not a raw waveform import and not sufficient independent clinical validation.
Sleep-EDF and other desired datasetsThe required accepted Sleep-EDF pair is unavailable; a partial acquisition is not a qualified source. PTT, RadLab and other named source requirements remain open.
Actual astronaut wearable dataNot verified from current repository. The current demo is not connected to astronaut devices or a medically validated live wearable.

What can honestly be claimed?

ASTRA can demonstrate persistent synthetic monitoring, quality-aware visualization, isolated crew data, deterministic scenario replay and offline attribution. It cannot establish actual disease sensitivity, treatment effectiveness, real sensor calibration or general predictive reliability.

What would a future sensor require?

A producer interface exists for authorized scalar telemetry, but a real deployment would need an actual device adapter, calibrated units/cadence, authenticated provenance, clock synchronization, missingness handling, privacy and source rights, clinical evaluation and new operational approval. A working POST route is only one small part of that work.

Documentation conflict: an older root README statement that no physiological dataset was downloaded is stale relative to the BIDMC numerics inventory. The dataset card identifies a real 7,644-byte public research file; it does not authorize feeding patient records into this demo.

7 · N01: security and privacy

Security has several separate jobs. Authentication identifies a session; authorization limits its actions; integrity checks detect altered records; privacy restricts who can see sensitive information. A local research prototype can implement these controls without being a production medical identity system.

Session mechanics

The demo role picker creates a session with a random 32-byte token. The database stores its SHA-256 hash, not the raw token. The browser receives an HttpOnly, SameSite=Strict cookie with a two-hour maximum lifetime. Server-side expiry is checked on later requests. Logout invalidates the session. Loopback binding limits ordinary access to the laptop; it does not make all local files or browser activity safe automatically.

ControlImplementation and consequence
Role permissionscontracts.mjs defines allowlisted actions. A researcher cannot acknowledge an alert just because research access exists. System administrator does not automatically have health-read scope.
Crew scopeAn astronaut session is bound to CREW-03. crew authorization rejects another crew ID; changing the URL does not expand access.
Private cognitionN10 checks actor/device, current consent and review-sharing eligibility. Demo administrator is not a universal private-data bypass.
Source / input validationQueries, regions, channels, metric IDs and request bodies are bounded and validated. An untrusted mesh label cannot become arbitrary SQL or a file path.
Audit integrityAudit entries include previous/current hashes. Append-only triggers protect selected history tables. A hash detects changed bytes; it is not encryption or a human scientific signature.
External scalar ingestAn optional timing-safe service-token check protects this producer path; if the configured token is absent, ingestion is disabled.

Safe request example

GET /v1/crew/CREW-03/anatomy?region=cardiovascular
Cookie: [existing session cookie; deliberately not printed]

Astronaut assigned CREW-03 → permitted eligible read
Same session requesting CREW-01 → 403 Forbidden
Expired / missing session → 401 Unauthorized

The cookie placeholder above is explanatory, not a credential to copy. The demo login proves engineering role behavior, not password-based identity assurance. Database-at-rest encryption, deployed TLS, real organization identity integration and regulatory certification are not established by the current loopback setup.

8 · N02: how monitoring really works

The active monitoring decision is deterministic code: the same eligible observations and detector state produce the same decision. It is not a Qwen judgment. Personal reference values and source-time persistence help distinguish a sustained authored change from a single value.

Personal deviation and quality gates

The reference center is a median. The scale is the larger of a metric floor and 1.4826 × median absolute deviation (MAD). The detector computes z=(value−center)/scale. For illustration only, center 68, scale 4.5 and value 86 gives z=4. This is a software-relative deviation, not a claim that 86 bpm is medically dangerous.

Current rule parameterRepository value / engineering meaning
Quality / freshnessMinimum confidence 0.7; fresh metric time bounded by max(5,000 ms, 3,000/sampling_hz). Poor data yields Gray.
Amber multi-signal / single-signalAt least two |z|≥2 signals for 90 s, or one |z|≥4 for 120 s.
Rapid change≥3 robust standardized units/minute sustained for 60 s within its rate window.
Red escalationTwo severe |z|≥4 signals for 180 s, or one |z|≥6 signal for 180 s, subject to eligibility/persistence logic.

Only new monotonic source observations advance persistence; holding a sample does not. Source changes reset relevant state. HR/HRV/respiration are excluded from resting-rule interpretation during activity. A missing or suspect signal cannot be silently counted as healthy. The displayed heuristic evidence score is not a validated probability.

Acknowledgement is not resolution or receipt

The engine records an authorized human actor/time and queues a stable case-report ID atomically. Pending case preparation can return a conflict. Communications preserves queue and receipt state across restart. Defaults include a 720,000 ms one-way delay and 128 kbps link; blackout/retry can delay further. N06 only reads these records—it does not create or acknowledge them.

9 · N03/N04: the browser application

The interface is an application made from HTML, CSS and JavaScript modules. N03 supplies correctness, routing/state behavior and performance engineering; N04 supplies the accepted cinematic navy/electric-blue visual language. A modern appearance is separate from scientific approval.

State and communication

app.mjs keeps the current identity, selected page, crew, view and latest mission snapshot. A shared fetch wrapper sends JSON requests to the same local origin. Server-Sent Events (EventSource) deliver mission updates through the mission stream. This is one-way server push; user actions still use explicit HTTP requests.

Request gates cancel obsolete reads. Session version checks also prevent late replies from updating a new session. Page changes and unmounts dispose components; page suspension aborts session-wide work and stops polling, then a compatible resume refreshes source state. Compatible selection is preserved separately from health records.

Reliability and accessibility

The frontend distinguishes loading, empty, denied, failed and stale states. A named service-availability region announces degradation without turning UNKNOWN into Green. Keyboard controls, visible focus, responsive tables, reduced motion and 200% zoom support alternate ways of using the system. Local cached synthetic snapshots are not a live backend connection; private case content is excluded from that fallback snapshot.

Why a fast API can coexist with a slow crew switch

An API may return small JSON in milliseconds while the browser still loads, verifies, decodes and uploads large geometry, initializes graphics and remounts a scene. Retained final acceptance measured an API p95 near 14.7 ms but crew switching including 3D remount around 8.2–8.9 s. These measure different work. Neither establishes physical presented-frame AC-20 performance.

10 · N05/N06: 3D anatomy and linkage

Three.js helps build a 3D scene; WebGL lets the browser use graphics hardware. A mesh is a surface made of triangles. GLB is a compact binary container for glTF geometry/materials. None of these technologies guarantees anatomical accuracy.

Renderer and asset identity

N05 loads three immutable licensed GLBs for body, skeleton and organs. Five semantic meshes represent body, skeleton, heart and two lungs. The source lineage is BodyParts3D 4.3 / FMA 3.0, 326 original source elements, credited to the Database Center for Life Science under CC BY-SA 2.1 Japan. The generic reference body is not a crew scan. Heart coverage is incomplete and independent fidelity review remains pending.

The scene uses a camera, lighting, materials and orbit controls. Detailed/coarse LOD tiers contain 663,277 / 253,117 triangles. The critical graphics payload is near the documented 20,000,000-byte budget. Hash validation, loading states, context-loss fallback and explicit reload protect against corrupt assets. Unmount disposes buffers, textures, materials, listeners and animation work.

N07 asks whether a source is authentic, permitted and suitable. N08 asks whether a supported recording can be parsed, preserved and replayed without losing identity or time. A hash is a fingerprint of bytes: matching it helps detect alteration, but does not prove scientific correctness or usage rights.

The waveform engineering path

The current N08 parser accepts its own explicitly synthetic ASTRAWV1 binary and ASTRACSVv1 CSV contracts. Metadata defines source, crew, channels, units, start time and rate. Binary samples use bounded float32 data; normalization preserves source/channel identity. Original bytes and 1–5 second channel chunks are stored with hashes in SQLite BLOBs, not re-created as a fabricated “live” stream.

Limits include 256,000 bytes, 1–60 s, 1–3 channels, 50–500 Hz, 64 revisions and 8 MiB per crew payload. Missing intervals remain missing. Experimental peaks are descriptive engineering outputs; PPG is not converted into a validated blood-pressure reading. N08’s original inactive timing descriptor and N06’s separately authorized archive reader should not be confused.

BIDMC usage rights retain ODC-By 1.0 and original notices; the card records that publisher-checksum verification is false. Single-record scope cannot supply independent clinical train/test evidence. Authentic source availability, anatomical linkage review and missing named sources remain external acceptance gates.

12 · N09: how fictional readings are made

A simulator is a controlled generator. ASTRA does not choose an arbitrary number every time a card is drawn. A seeded pseudo-random generator, authored personal references, circadian variation, noise and scenario effects produce reproducible source-time observations. Software can then commit and replay them through the real pipeline.

Six fictional crew, independent assignments

CrewIdentity
CREW-01 / VEGAElena Voss · Commander
CREW-02 / ATLASMarcus Chen · Mission pilot
CREW-03 / NOVAAmara Okafor · Science officer
CREW-04 / KITEYuki Tanaka · Systems engineer

The generator version is n09-source-time-v1. Calibration archives use 720 hourly draws per metric—30 authored days—not 30 days of measured astronaut data. A default seed of 42017 plus crew-specific structure supports repeatability. Box–Muller-style Gaussian sampling and repository arithmetic are implementation choices, not learned physiology.

Scheduling, quality and replay

Runs permit defined cadences (30, 60, 300, 1,800 or 3,600 seconds) and bounded durations up to seven days, with frame/run limits. Real-time progression and manual advance both move mission time. Pause holds progression; sources can become stale. Stop retains evidence; reset creates new execution history. Versioned events and request IDs prevent duplicate commands.

The ten presets are nominal, controlled-hr-rise, cardiorespiratory-drift, sleep-debt-cardio-drift, sleep-fatigue, post-exercise, radiation-spike, sensor-dropout, contradictory-sensors and communication-blackout. Some alter quality or communications rather than physiology. Scenario replay respects what source/record was known at the cutoff, so later reset state must not leak into an earlier view. This is a test generator, not a physical wearable or validated disease model.

13 · N10: sleep, exercise and cognition

N10 combines non-private mission context with optional private personal inputs. Its important distinction is between describing records and diagnosing a condition. The implementation can count sleep duration or exercise adherence without proving that a particular person has a clinical disorder.

Versioned records instead of silent edits

The ledger appends revisions with crew identity, record kind, source time and knowledge time. Sleep intervals, stages and schedules support completed-duration and coverage calculations. A later correction changes the eligible projection without rewriting an earlier original. Historical views consider when that correction became known.

Record / calculationMeaning and limitation
Sleep sessions and stagesCompleted intervals, available stage labels and gaps; stage availability is not a new sleep-classification model.
Schedule and descriptive shortfallCompare a plan with eligible recorded sleep. A shortfall is an accounting result, not a medical sleep-debt diagnosis.
Exercise plan / session / movementTrack duration, workload context, adherence and available movement entries; not a personalized treatment prescription.
Reaction taskFive voluntary timed trials with readiness/false-start handling; a personal reference requires enough eligible same-person observations.
Mood / fatigue inputOptional self-report under consent; not a psychiatric or clinical cognitive score.
Review sharing and privacyCurrent consent plus actor/device and role rules determine visibility. Historical timestamps alone do not bypass current privacy restrictions.

The Sleep & resilience screen implements the allowed forms and history. The voluntary cognitive utility is separate. N06’s conceptual head context can describe completed non-private sleep but must not expose another actor’s reaction trials or mood. Missing coverage, insufficient personal reference, denied sharing and revoked consent remain explicit unavailable states.

Why the dual clock matters

A session may end yesterday but be entered today. Yesterday’s replay must not pretend the system already knew it. Source time and knowledge time solve different questions.

14 · N11: anomaly evaluation and rejection

An anomaly is an observation unusual relative to a reference. Unusual does not mean disease. N02 uses fixed review rules; N11 compares advanced candidate methods in a separate research/shadow evaluation. A candidate never earns operational authority just because its code runs.

Three kinds of research logic

MethodSimple explanation / implementation role
Robust personal referenceDescribe a person’s baseline and scale before scoring changes; source quality and eligible history matter.
EWMAExponentially weighted moving average gives more weight to recent values while remembering older ones. It can emphasize sustained drift.
Isolation ForestBuild random partition trees. A point isolated after fewer splits may be more unusual than points requiring many splits. It is not a supervised medical-diagnosis model.

How Isolation Forest works

Imagine repeatedly splitting a scatterplot with randomly chosen features and cut points. A lone remote point is often separated quickly. A dense cluster usually takes more cuts. The algorithm averages path lengths and converts them to a rarity score. Its usefulness depends on feature scaling, population, quality, training distribution and a defensible evaluation design.

ASTRA implements candidate research logic in repository JavaScript, including reference fitting, feature extraction, EWMA and forest scoring. This is not evidence of a hidden online AI service or a currently deployed scikit-learn detector. Research job/result/event records preserve policies and outcomes so failed results are not erased.

The actual outcome matters more than the model name

Isolation Forest was rejected: the retained synthetic evaluation reports 0 true positives and 4 false negatives on four authored detection cases, plus 44 false episodes on the already-seen robustness material. It remains rejected/disabled. The four misses must not be presented as a successful detector.

Tier A/EWMA outcomes on four authored events do not establish clinical sensitivity either. Authored cases are engineering controls, not independent real-patient outcomes. Choosing or tuning a model after seeing those cases also prevents relabeling that set as unseen validation.

What the application may show

Evidence & provenance exposes scoped model evidence and saved research state to permitted roles. It must preserve REJECTED / NOT_PROMOTED labels. The active N02 alert authority remains deterministic monitoring. Starting another candidate fit or research worker is not part of this documentation or presentation scope.

15 · N12: understanding forecasts

A forecast estimates a later value from earlier observations. It is not a diagnosis or a guarantee. ASTRA implements three understandable methods so candidate complexity can be compared with a trustworthy baseline. Its research answers can legitimately be UNKNOWN.

PersistenceRepeat the last eligible value. A strong baseline when there is little dependable trend.60, 62, 64 → 64
OLS / linearOrdinary Least Squares chooses the line minimizing squared vertical errors. Fit value = intercept + slope × time.At times 0,1,2: 60,62,64 → at 3: 66
Theil–Sen / robustCompute pairwise slopes; take the median slope and a median intercept. Often less sensitive to isolated outliers than OLS, but not immune to bad data.Same clean sequence → slope 2 → at 3: 66

These are arithmetic examples, not crew readings or validated clinical forecasts. A forecast can fail even when a fitted line looks smooth. The future may change, samples may be missing and the apparent trend may be an artifact.

Coverage, horizons and reference units

The full N12 protocol checks a bounded recent history, good coverage, metric units, source/knowledge cutoffs and a current sample. Horizons are 5, 15, 30 and 60 minutes. It standardizes against a same-person mean and sample standard deviation using n−1, unlike N02’s robust median/MAD reference. These scales must not be described interchangeably.

15 · Forecast evidence, not promises

Intervals and abstention

N12 forms empirical residual-based intervals using a calibration quantile aimed at nominal 90% coverage. The rank is based on ceil((n+1)×0.9), with a minimum calibration count. This is a target of the procedure, not a guarantee that every metric/horizon achieved 90% coverage, and not a confidence percentage that a person is safe.

The pipeline rejects or withholds output for inadequate coverage, stale sources, incompatible units/policies, future or duplicate timestamps, unavailable selection, rejected candidates and unsupported extrapolation. A finite output from a simple formula is not enough to qualify the answer.

What is a 384-dimensional embedding?

Embeddings represent text numerically: MiniLM emits 384 values. Tokenization creates model inputs; masked mean pooling combines tokens; normalization controls vector length. Cosine similarity compares directions, not truth.

21 · APIs, HTTP and local networking

An API is a contract for program requests. HTTP carries those requests; REST-style routes identify resources and use verbs such as GET (read) and POST (submit an action). JSON represents objects and lists as readable text. localhost means your own machine; http://127.0.0.1:3000 selects its local ASTRA server on port 3000.

ASTRA serves static browser files and API routes from the same origin. The frontend therefore does not need a second cloud endpoint or a separate React dev server. Most authenticated reads use the existing cookie; they are not publicly authorized simply because the URL is local.

24 · Real-world value and future work

Space missions may face communication delays, limited bandwidth and periods without immediate ground assistance. A local tool that preserves observations, shows quality, supports human review and makes evidence available offline could be useful in that setting. The current prototype explores those engineering needs; it does not prove suitability for an actual mission.

What the implemented prototype contributes

  • A reproducible synthetic scenario can demonstrate exactly how an observation becomes a persisted review event, rather than an unexplained colored card.
  • Source and knowledge timestamps let replay distinguish an earlier event from information learned later.
  • Crew-bound anatomy offers navigation into permitted data without pretending to localize disease.
  • Offline quotations, explicit abstention and separate model-promotion gates keep attribution distinct from unsupported conclusions.

25 · Judges’ questions 11–20

11 · How does forecasting work?

Short answer: Persistence repeats a value; OLS fits a line; Theil–Sen uses a median slope.

Technical: The full N12 protocol also checks chronological history, calibration and supported horizons.

Do not claim: That a plotted line guarantees a future reading.

12 · Are predictions medically reliable?

Short answer: Not established. Qualification is synthetic engineering only.

Technical: Four registry cells qualify within that scope; twelve are rejected and operational promotions are zero.

Do not claim: Clinical accuracy or universal 90% interval coverage.

13 · Can ASTRA run offline?

Short answer: Yes, the supported local demo can, with its dependencies and assets already present.

Technical: Node serves the frontend/API; SQLite and retained evidence are local.

Do not claim: That missing models/assets will download offline or all cloud-era data are available.

14 · Does it need an API key?

Short answer: No remote API key is required for the current demo.

Technical: Local Qwen would not need a cloud key, but current native execution still needs valid authority.

Do not claim: A mandatory OpenAI, NASA, Supabase or cloud-Qwen account.

15 · Where is the database?

Short answer: At the path selected by ASTRA_DB.

Technical: The CLI default is data/runtime/astra.sqlite; the safe demo uses a fresh temp file and reuses it on recovery.

Do not claim: That artifacts/ is the one live database or sealed fixtures may be reused.

16 · Why SQLite?

Short answer: It gives local transactional storage without a separate server.

Technical: WAL, constraints, append-only histories and request identities support durable prototype behavior.

Do not claim: Automatic encryption, medical certification or mission-grade high availability.

17 · How does anatomy connect with readings?

Short answer: An allowlisted region maps to permitted crew metrics.

Technical: N06 validates crew, source and cutoff, then reads observations and existing N02/N08/N09 context.

Do not claim: An inferred organ-specific disease map.

18 · Does anatomical highlighting diagnose disease?

Short answer: No. It selects an information context.

Technical: The licensed generic mesh is not a personal scan; HR/RR timing is illustrative and quality-gated.

Do not claim: Heart disease from an elevated heart-rate observation.

19 · How are citations verified?

Short answer: The source, window and exact quoted text are checked.

Technical: Hashes and IDs bind the quote to the original publication/version/page span.

Do not claim: That exact attribution proves relevance, entailment or applicability.

20 · How do you prevent hallucinations?

Short answer: Bound sources, separate support checks and abstain when evidence is insufficient.

Technical: Prompt text is untrusted data; invented references and unreviewed positive rules cannot pass the governed path.

Do not claim: That an LLM is hallucination-free or a measured general rate exists.

26 · Technical glossary

Frontend. The browser interface a user sees and controls.

Backend. The local service that validates, reads, computes and stores results.

API. An agreed interface for requests between programs.

Database. An organized store of records with defined read/write rules.

SQLite. An embedded database engine using local files.

JSON. A text format for objects, lists and values.

REST. A resource-oriented style of HTTP API design.

HTTP. The request/response protocol used by the browser and server.

Localhost. Your own machine, commonly addressed as 127.0.0.1.

Node.js. The runtime executing ASTRA’s server-side JavaScript.

JavaScript. The programming language used across ASTRA’s main implementation.

Synthetic data. Intentionally generated data, not measurements from the represented person.

Real-world data. Observations collected from an actual source/population, subject to rights and context.

Telemetry. Time-stamped measurements transmitted or recorded for monitoring.

Sensor. A physical device measuring a property of the world.

Waveform. A sequence of signal samples across time.

Sampling rate. Samples recorded per second, measured in hertz (Hz).

Simulation. Software generation of controlled scenarios or observations.

Deterministic. Reproducible output for the same inputs and state.

AI. A broad term for computational methods performing intelligent-seeming tasks.

Machine learning. Methods that fit patterns from data rather than only fixed rules.

LLM. A large language model trained to predict/generate text.

Qwen. The model family used in ASTRA’s local text-generation research.

Quantization. Reducing numerical weight precision to save model resources.

Embeddings. Learned numerical representations of text or other inputs.

Retrieval. Finding existing relevant items or text passages.

RAG. Retrieval-augmented generation: give retrieved context to a generator.

Hallucination. A fluent generated statement not supported by reliable evidence.

Anomaly. An unusual pattern relative to a chosen reference.

Forecasting. Estimating later values from earlier eligible information.

Linear regression. Fitting a line relating input time/features to an outcome.

Isolation Forest. Random partition trees scoring how quickly points become isolated.

Agent. A system coordinating bounded actions or tools toward a task.

Tool calling. Invoking a defined external function with structured arguments.

Three.js. A JavaScript library for constructing and rendering 3D scenes.

WebGL. A browser graphics interface for accelerated rendering.

Mesh. A surface described by vertices and triangles.

GLB. A binary glTF container for 3D geometry/material assets.

Provenance. The origin, version and transformation history of information.

Hash. A content fingerprint useful for detecting changed bytes.

Authorization. A decision that a particular actor may perform an action.

p95 latency. A timing at/below which about 95% of the sampled requests fall.

Scientific validation. Independent evidence that a method is suitable for its claimed use.

Abstention. Explicitly withholding an answer when required support is absent.

Cold recovery. Restoring committed state in a newly started process.

Idempotency. Repeating an identified request without duplicating its committed effect.
