# N15 governed offline answering contract v1

Official module: **Offline language-model assistance**, R41/R43/R57, with source/QA dependencies R42/R59 and full N14 prerequisite. Twelve audit clauses: model identity/admission; verified retrieval; prompt packing/injection; independent support; output verification; staged response; rule lifecycle/review; scoped offline service; audit durability/recovery; N13/N14 compatibility; inactive N16; end-to-end/QA/resources. They subdivide authoritative N15-01/05/06/08/10/11 requirements, not twelve invented official IDs.

New request astra.n15.answer-request.v1: mode source_quotation or factual_answer; bounded question≤384UTF-8bytes; explicit generation none/local_model; optional exact window_id for quotation only. No role/crew/model/corpus/path/SQL/tool parameters. Trusted launcher researcher/demo_admin capability consumes only public retained research; local code capabilities are not a new HTTP identity provider. Private cognition/crew/live data are never inputs. General clinical/personal/tool requests reject. Quotation mode requires the unchanged N15-10 exact command `Quote the complete source passage window-<SHA>.` and matching canonical window. It cannot relabel a factual question as quotation-only.

Stage outputs distinguish request validation, immutable N13/N14 load, lexical retrieval or exact canonical lookup, source attribution, relevance, factual support, prompt packing, inference admission/execution, post-generation validation and audit readiness. An ineligible/missing/conflicting/unknown stage returns structured ABSTAIN with no outward quotations. Every factual answer remains ABSTAIN because no positive support rule is approved. Hz/dB missing facts retain the existing narrow numeric veto; other unknown numbers/units/relationships never gain support. Source reproduction is a functioning positive path without asserting factual relevance or clinical support.

Tool-free prompt uses frozen n15-05 policy/1536-byte budget, original evidence, fixed ordering/dedup, no omitted text disguised as complete. Query/evidence reject ChatML delimiters and untrusted instruction patterns. No arbitrary prompt/grammar/token/sampler/model changes are caller-controlled. Native generation must return exact frozen SELECT/ABSTAIN grammar, selected ID among supplied evidence, verified complete canonical quotation/citation/role/scope and separate N15-10 post-check. Free generated prose, altered IDs/citations/claims never escape. Current factory creates no native execution capability; local_model produces MODEL_NOT_AUTHORIZED without invoking a provider. QA provider injection exists only in a pure test kernel; outputs remain generated_by_llm:false / QA_SIMULATED, never fresh native qualification. Timeouts/cancellation discard late results; they do not claim native termination without actual sandbox execution.

Model identity is fixed Qwen/Qwen2.5-0.5B-Instruct-GGUF revision9217f5db79a29953eb74d5343926648285ec7e67,491400032bytes,SHA74a4da8c9fdbcd15bd1f6d01d621410d31c6fc00986f5eb687824e7b93d7a9db. Existing llama.cpp b11669/v0.7.0 and exact17-file manifest remain. Native gate requires separately approved current startup count/resource policy, original network/filesystem/seccomp containment, fixed backend/dependencies, durable observer and first-failure behavior. Missing/wrong hash/version or absent authority cannot fall back to cloud/model substitution.

Support lifecycle records are content-addressed external declarations, not authenticated scientific decisions. Valid transitions DRAFT→CANDIDATE→DETERMINISTICALLY_TESTED→REVIEW_PENDING→REVIEWED_ACCEPTED/REVIEWED_REJECTED→OWNER_AUTHORIZED→ACTIVE; rejected/active records may be revoked or superseded. Accepted/owner states require exact source/rule/packet hashes, distinct declared identities, dated sign-off references, checks/reasons and resolved disagreements. Sequence/hash chain detects omissions/duplicates/reorder/truncation. Projection labels external claims UNAUTHENTICATED; **effective_active remains false** until a separately authorized externally authenticated integration exists. No positive rule matcher is implemented. Existing real proposal projects REVIEW_PENDING with zero supplied human records; synthetic QA events exist only in disposable memory.

Audit astra.n15.audit.v1: normalized request, source/retrieval/model/prompt identities, stage chain, response hash, rule state and code pins. Strict bounded records, fixed task or astra-n15-* OS-temp roots, exclusive stage/write/sync/rename/parent ACK/COMMITTED/readback, idempotent content ID. Recovery validates current sources/code and recomputes deterministic governed decisions; it **never replays generation**. For future generated audits, strict recorded-output validation must be used rather than inference replay. Current production audits contain no native output. Incomplete/failed ACK/partial records remain visible and fail closed.16audits/root,2MiB/audit,4096response bytes,120s cooperative publication deadline; no global/hard resource claim. No PDF/model/SQLite copies or old-history cleanup.
