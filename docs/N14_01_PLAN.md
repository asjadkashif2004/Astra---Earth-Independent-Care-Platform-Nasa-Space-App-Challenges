## Embedding contract — required verification, not a measured implementation

1. Load only the exact model revision's `tokenizer.json`, `tokenizer_config.json` and special-token metadata. Use its BERT normalizer/pre-tokenizer, WordPiece vocabulary, unknown-token handling and postprocessor. Honor lowercase, accent, whitespace/control-character, Chinese-character and special-token semantics from those files; do not guess normalization defaults or hardcode token IDs. The [standalone tokenizer documentation](https://raw.githubusercontent.com/huggingface/tokenizers.js/v0.2.0/README.md) lists these component types, but exact parity and offset support still need proof.
2. Encode a single text segment/window as `[CLS]` + at most254content WordPieces + `[SEP]`: **256tokens total**, including specials. Use deterministic windows/32content-token overlap within the existing reviewed spans; retain exact UTF-16 source offsets. Longer text must be explicitly windowed or rejected, never silently truncated. The publisher tokenizer config's512-token capacity is not permission to use512; the approved encoder policy remains256. Do not recover offsets by searching decoded strings or silently retokenizing mid-word windows. Stop if correct offsets cannot be established.
3. Emit equal-length integer `input_ids`, `attention_mask` and, where required by the verified graph, `token_type_ids`. Mask actual tokens, including CLS/SEP, with1; PAD with0. Single-segment type IDs are0. Pad only with the verified PAD ID; any batch padding counts within256. Reject empty/whitespace-only queries, mismatched lengths, invalid IDs or all-zero masks.
4. **Expected ONNX contract to check after authorized model acquisition:** `input_ids`, `attention_mask`, `token_type_ids` are int64 tensors of shape`[batch,sequence]`, represented by `BigInt64Array` with exactly matching dimensions. Expected output `last_hidden_state` is float32`[batch,sequence,384]`. These names/types/shapes have not been inspected from a local model original. Inspect actual model/session metadata before feeding; never silently alias names, cast to int32, invent missing inputs or assume an already pooled output. If the pinned graph differs, stop and document the evidenced adapter decision before proceeding. Require CPU execution provider; no automatic GPU/WASM fallback.
5. For each output dimension compute `sum(token_embedding * attention_mask) / sum(attention_mask)`, excluding PAD and retaining all other unmasked tokens, including specials. Accumulate deterministically, then L2-normalize the384-dimensional mean vector. Reject zero denominator, zero norm, nonfinite entries and unexpected shape; do not manufacture a usable vector. Record float32 storage, operation order and normalizer version. Pooling must not be applied twice if the graph output is already a sentence vector. [Publisher reference algorithm](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2).

## Bounded claim checks and abstention

The single encoder is **not** an entailment/NLI or generative model. Claim checking must be conservative: identify exact source-text matches with preserved qualifiers/role/version; flag partial scope, recognized incompatibility/conflict, missing evidence or excluded claims. Free paraphrases whose support cannot be established by explicit source checks return insufficient support. Do not classify arbitrary medical entailment using cosine scores or pretend to detect all scientific conflicts.

Output states may include `source_text_match`, `partial_support`, `conflicting_evidence` and `insufficient_support`, always research-only/pending review. A literal text match verifies provenance, not that the publication is universally true or clinically applicable. Absence of a recognized conflict is not proof of consensus.
