### Proof method and important discrepancies

For ten fixed refs, preserved GitHub compare responses bind full `base_commit`, `merge_base_commit`, status and candidate head. `ahead` plus `base == merge_base` establishes ancestry; this is not inferred from dates or build numbers. Full commit metadata/patches were inspected. Compare URLs use `per_page=1&page=2` to avoid the large first-page changed-file list; ancestry fields remain present and were checked.

The vocabulary fix has a complete direct parent chain: candidate contains `fb85a288…` (b5662), whose parent is `40643edb86eb10b471b0f57d4f3f7eb0e06a0df7`, whose parent is actual fix `3cfbbdb4…`. Both parent records and the actual fix patch are preserved. The RPC RCE fix and uninitialized-GGUF fix additionally have direct compare-to-candidate records.

The uninitialized-GGUF fix was committed **2024-04-26T07:41:53Z**. b2740 resolves to CI commit `d4a9afc1009f0da88d04b2c5f672d81d5ae94675` at **07:27:49Z**, before that fix. Direct comparison reports the tag **behind** the actual fix. This demonstrates why the advisory's patched-version string alone cannot establish security. Candidate ancestry to the actual fix is verified, so the original range discrepancy need not be guessed away.

Relevant source snapshots preserve current GGUF bounds checks, RPC tensor validation and graph-node guard. These are targeted inspections, not full formal verification, proof against regressions, exploit testing or a guarantee that arbitrary model files/queries are safe. Public advisory inventory is reused, not a new comprehensive audit. Vendor vulnerabilities and an eventual installed dependency graph remain separate unresolved checks. [Pinned upstream security policy](https://raw.githubusercontent.com/ggml-org/llama.cpp/620d2225cc436ab0b001e3200e590e3b286ef9ab/SECURITY.md) calls for isolation; its disclosure scope/exclusions are not used to dismiss an advisory.

The CPU archive build also enables server and RPC, so its label is not proof of a minimal attack surface.
