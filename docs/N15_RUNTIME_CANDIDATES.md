## Runtime candidate and remaining qualification

The [official llama.cpp project](https://github.com/ggml-org/llama.cpp) documents local C/C++ inference and GGUF usage; its [CPU build guide](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md) provides a CPU backend. Prefer one publisher-provided standalone Linux x64 CPU executable/archive, without Python/PyTorch, Transformers.js, Sharp, Ollama, GPU packages, daemon/service installation or model autoloading. This is a runtime recommendation, **not a version selection or proven binary compatibility**. Record a full release/commit, artifact identity, exact size and trusted digest before acquiring; no `latest`, installer script, package-manager substitution or automatic source build.

The [runtime license](https://github.com/ggml-org/llama.cpp/blob/master/LICENSE) is MIT; retain its copyright/permission notice. Prebuilt dependencies can have additional licenses/redistribution conditions. Their actual ABI/SONAME/instruction requirements, dependency graph, notices, archive expansion size, security advisories and CPU-only native behavior are unverified until a concrete artifact is qualified. Stop on unresolved serious security findings or missing prerequisites; no sudo/system package changes are approved.

The [native CLI documentation](https://github.com/ggml-org/llama.cpp/blob/master/tools/cli/README.md) exposes explicit model paths, offline/thread/context/token limits; these flags must be checked against the selected release rather than assumed stable. Use no hub/model URL options, environment-inherited endpoints or remote server modes. The [grammar guide](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md) supports constrained outputs but documents schema limitations: grammar validity is not factual/citation correctness. Use a small audited local grammar and a separate full deterministic validator; no remote schema references or downloaded template code.

Both candidates can in principle operate offline once the correct assets are present. Actual native loading, complete tokenizer/chat-template metadata, Qwen BPE/special-token behavior and local no-network execution remain future tests. N14's MiniLM WordPiece tokenizer is not the generative model's tokenizer. No GPU/iGPU capability or model quality advantage is assumed.

**Recommendation:** qualify only the 0.5B candidate first for the minimum genuine generation slice. The 1.5B pair is an alternative requiring a new decision, not a second download or an inferred upgrade path. Exact metadata gaps and runtime pins remain blockers to execution; they do not prevent delivering this documentation proposal.
