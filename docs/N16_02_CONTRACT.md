## Implemented boundary

`GET /v1/agent/fixture-trace` accepts no query, path selector, role, crew or run argument. Other methods/query input reject. The existing session establishes trusted identity; existing `read` permission is checked against fixed CREW-03 before artifact IO. Astronaut self scope remains; system-admin does not gain read access. Existing read roles may inspect this synthetic archive, regardless of case permission. No new privilege is granted. JSON responses use the existing no-store/security headers. An authorized request returns AVAILABLE or UNAVAILABLE; authorization failures retain existing401/403 handling.

[fixture-trace-view.mjs](../services/agent/fixture-trace-view.mjs) pins all six original file byte counts/hashes, the fixed run/crew and fixture/manifest identities. Only that run's exact inventory is opened. Existing O_RDONLY/O_NOFOLLOW bounded reads and fd-anchored directories reject symlinks, path changes and oversized/substituted files. The trusted-library `root` QA seam is never sourced from HTTP. No artifact is served through an arbitrary static-file endpoint.

Validation covers the versioned18-event schema, UTC ordering, sequential hash chain, terminal checkpoint, fixed four request/validate/start/complete relationships, trusted recorded scope, validated arguments, call/result references, full result hashes, source identity, flags, actual-read receipts and source freshness/quality. The original read-only N16-01 recovery routine also verifies complete committed results with zero replay; its results must match the already pinned originals. This neither creates a new run nor rewrites/repairs any trace. Hash pins provide consistency against retained originals, not an independent signature or comprehensive tamper-proof system.

AVAILABLE is an archived evidence state, separate from tool execution and data availability. This sole approved run has four COMPLETED calls, three KNOWN data results and one UNKNOWN risk source. No failed/cancelled demonstration is invented. Renderer-only fixtures check FAILED/CANCELLED/TIMEOUT/DENIED text semantics; these are QA controls, not newly recorded executions. Incomplete/corrupt/unverified source or trace state yields UNAVAILABLE with no partial successful cards. Stale observation provenance fails validation. Missing risk coverage is a valid UNKNOWN, not a trace failure, new alert or all-clear.

Freshness is **recorded mission-time freshness** at `2026-11-14T11:00:00.000Z`, not freshness relative to host wall time. Archived execution UTC and mission observation/receipt times remain distinct; Earth receipt is explicitly absent/onboard-only. The panel never labels the saved103/min as a current measurement. Reference baseline center68/min is authored synthetic schema data, not a learned personal archive. Opening the panel, live telemetry updates and Earth-view selection cannot dispatch a tool or place fixture records into operational state.

[fixture-trace.mjs](../apps/mission-control-web/fixture-trace.mjs) renders escaped text only, one fixed GET per mount, no automatic polling or action controls. Native details/summary controls and focusable, labeled provenance regions support keyboard inspection; status text has polite atomic announcements and does not depend on color. Failed requests, stale sessions and removed panels cannot publish successful or late data. Existing API request cancellation/session checks apply. The existing template/no-LLM notice and all case/acknowledgement/Earth-delivery handlers remain unchanged.

The existing application retains its normal service lifecycle and session lookup; the new adapter does not construct or call Store/Engine to obtain fixture data. Focused QA uses isolated trace copies, the existing selective DOM harness and source-level route/render execution with trusted mocks; no operational service/DB/detector/model is started. It is not a full browser, CSS/layout, screen-reader or end-to-end operational acceptance certification.

Full dependencies/reviews remain open. No N15 rule activation, Qwen integration, extra tool, medical claim or production readiness is implied. This extension authorizes only the delivered saved-trace presentation; no further execution or integration is automatic.
